# Python Issue Crawler

개발 트러블슈팅과 알고리즘 문제 풀이를 위한 콘텐츠 수집·작성·검증·발행 파이프라인입니다. Python 기반으로 소스 수집, LLM 기반 초안 생성, 품질 검사, MDX 렌더링, Git 발행 과정을 모듈화했습니다.

## 주요 기능

- **주제별 파이프라인:** 트러블슈팅, 알고리즘 문제 풀이, GitHub 오픈소스 분석을 독립적으로 실행
- **오픈소스 후보 탐색:** 웹, 개발 도구, 인프라, 데이터베이스, 보안, 게임, 생산성 등 다양한 분야의 인기/최근 활동 저장소 탐색
- **수동 후보 선택:** 오픈소스 분석 글은 사용자가 저장소를 직접 선택한 뒤 기존 작성·검수·MDX 파이프라인을 실행
- **자료 수집:** 공개 기술 Q&A, GitHub, 알고리즘 문제 등 설정된 소스에서 참고 자료 수집
- **초안 생성:** 수집한 자료를 바탕으로 한국어 기술 노트 생성
- **품질 검사:** 필수 섹션과 코드 블록 등 구조적 조건을 확인하고 필요한 경우 재작성
- **중복 방지:** 이전에 처리한 소재 이력 관리
- **MDX 출력:** 블로그에서 사용할 수 있는 파일과 관련 자산 생성
- **선택적 발행:** 설정된 Git 저장소에 변경사항을 커밋하고 push
- **진단 및 로그:** 소스 수집 실패와 파이프라인 실행 결과를 확인할 수 있도록 로그 제공

## 처리 흐름

```text
소재 탐색
   ↓
참고 자료 수집 및 정리
   ↓
콘텐츠 초안 생성
   ↓
구조 및 품질 검사
   ↓
MDX 렌더링 및 자산 저장
   ↓
로컬 결과 확인
   ↓
설정에 따라 Git 발행
```

## 구성

```text
pipeline/
  engine.py              # 주제별 파이프라인 실행
  scheduler.py           # 주기 실행
  config.py              # 환경 설정
  history.py             # 소재 중복 방지
  crew_builder.py        # 에이전트 구성
  topics/                # 주제별 처리 흐름
  sources/               # 외부 자료 수집
  output/                # MDX 렌더링
  publish/               # Git 발행
  verify/                # 구조 및 품질 검사
```

## 요구 사항

- Python 환경 및 `uv`
- LLM API 호환 엔드포인트와 API 키
- 자료 수집 및 Git 발행에 필요한 네트워크 접근 권한
- 발행을 사용할 경우 대상 저장소의 로컬 clone과 Git 인증 설정

## 설치

```bash
uv sync
```

프로젝트 루트에 `.env` 파일을 만들고 필요한 설정을 입력합니다. 실제 키나 토큰은 저장소에 커밋하지 마세요.

필수 설정 예시:

```dotenv
OMNIROUTE_API_KEY=your_api_key
PUBLISH_TARGETS=[]
```

실제 발행 대상은 `.env.example`과 설정 설명을 참고해 구성합니다.

## 실행

메뉴에서 실행:

```bash
uv run engine.py
```

트러블슈팅 노트 한 편 생성:

```bash
uv run engine.py --topic troubleshooting
```

알고리즘 노트 한 편 생성:

```bash
uv run engine.py --topic algorithm
```

두 주제를 각각 한 편씩 생성:

```bash
uv run engine.py --topic both
```

생성만 하고 발행하지 않기:

```bash
uv run engine.py --topic both --no-publish
```

환경 및 소스 연결 진단:

```bash
uv run engine.py --diagnose
```

주기 실행:

```bash
uv run scheduler.py
```

## 설정과 발행

- `PUBLISH_TARGETS`에서 발행 대상 저장소, 콘텐츠 경로, 자산 경로와 브랜치를 지정합니다.
- `AUTO_PUSH` 설정에 따라 검사된 결과를 자동 발행하거나 로컬에서 검토할 수 있습니다.
- 처음 설정할 때는 자동 발행을 끄고 결과물을 확인하는 것을 권장합니다.
- 발행 대상 저장소의 미커밋 변경사항이나 인증 오류가 발생하면 실행 로그를 확인하세요.

자동 검사는 콘텐츠의 정확성이나 적절성을 완전히 보장하지 않습니다. 발행 전에 코드, 설명, 출처 링크와 라이선스를 확인하는 것이 좋습니다.

## 한국어 + 영문 MDX 발행

- 영어 번역은 `PUBLISH_TARGETS` 항목 중 하나 이상에 `en_posts_dir`가 설정된 경우에만 실행됩니다. 비워두면 번역 호출과 영문 파일 생성을 모두 건너뜁니다.
- 한국어 검수가 통과한 글만 영어로 번역합니다. 번역은 최대 3회 검증하며, 코드블록 개수와 코드 밖 한글 잔존 여부를 확인하고, 코드 내용이 바뀌면 원문 코드블록을 복원합니다.
- 영문 MDX는 `output_files/<주제>/en/<slug>.mdx`에 저장되고, 대상 저장소의 `en_posts_dir`로 한국어 MDX와 같은 커밋에 포함됩니다. 이미지 자산은 한국어판과 공유합니다.
- 예시: `"en_posts_dir": "src/app/[locale]/blog/posts/en"`. 영어판이 필요 없는 대상은 `"en_posts_dir": ""`로 설정하세요.
- 번역이 실패해도 한국어 결과물과 기존 발행 흐름은 유지됩니다. 단, 대상 사이트의 영어 라우팅 및 MDX 로더 경로는 별도로 확인해야 합니다.

## 품질과 실패 처리

파이프라인은 결과물의 구조를 검사하고, 형식이 잘못되었거나 필수 요소가 빠진 경우 재작성을 시도합니다. 재시도 횟수와 모델 설정은 환경 변수로 조정할 수 있습니다. 최종 검사를 통과하지 못한 결과는 자동 발행 대상에서 제외하고 로그를 통해 원인을 확인할 수 있도록 합니다.

## 개발 방향

- 수집기와 주제별 파이프라인의 결합도 낮추기
- 외부 소스의 실패를 구분해 진단 가능성 높이기
- 생성 결과의 구조적 품질과 출처 추적성 개선
- 생성, 검토, 발행 단계를 독립적으로 실행할 수 있도록 유지
